# AI-002 挂载期 ref 回调触发时元素 `isConnected === false`

**状态**：🟢 已修复（2026-08，方案 A）
**发现自**：tabs → CompositeList → `register(node)` 内 `node.isConnected` 守卫挂载期恒全过滤
**关联**：AI-001（map 空 → watch 逻辑空跑）

---

## 问题描述

组件挂载过程中，宿主元素的 ref 回调触发时，其**所有祖先链尚未 appendChild 到文档**，`element.isConnected === false`。这导致依赖 isConnected 守卫的代码（如 `getCompositeListSnapshot`）在挂载期将刚注册的节点全部过滤 → map 空 → `onMapChange` 收到空集合。

**实测复现**（`test/_tmp-ai2.test.tsx`）：

```
[纯宿主嵌套] ref 回调时刻 → {"self":false, "inDoc":false, "parentTag":"DIV"}
[含组件层]   ref 回调时刻 → {"self":false, "inDoc":false, "parentTag":"DIV"}
[对照] happy-dom 游离树 → isConnected=false
[对照] 接入文档后       → isConnected=true
```

DOM API 本身正确，问题出在框架的挂载插入顺序。

---

## 根因

```ts
// packages/core/src/runtime/renderer.ts:206-218 — mountVNode 宿主元素
const el = createElement(vnode.type)
vnode.el = el
patchProps(null, vnode.props, el)
vnode.__avChildren = patchChildren(null, vnode.props?.children, el, undefined, parent)
//                                               ↖ 子元素挂载（递归），子 ref 在此触发
//                                                 此时 el 尚未 appendChild → isConnected=false
container?.appendChild(el)       // ← 父元素接入文档
applyRef(vnode.props?.ref, el)   // ← 自己的 ref（此时已连接）
```

**问题链**：`patchChildren` 在 `appendChild` 之前→ 子元素 ref 触发时，当前宿主元素及其所有祖先均为游离状态 → `isConnected === false`。

---

## 与 React / Vue 的对比

### React

React 的提交顺序是**前序先插入**：fiber 的 Placement effect 先 `insertOrAppendNode` 将宿主元素加入父 DOM，再处理子 fiber 的 effect。因此子元素 ref 触发时（`commitAttachRef`），整条祖先链已在文档中。

```
commitPlacement(parent)          // parent插入DOM
  → commitNestedUnmounts(...)
commitMutationEffects(child)     // 处理子元素
  → commitPlacement(child)       // child插入parent（parent已在DOM→child连接）
  → commitAttachRef(child)       // child ref触发→isConnected=true
```

### Vue 3

Vue 3 的挂载顺序与 ActView 相同（**后序**——`hostInsert` 在 `mountChildren` 之后），但 Vue 3 **把 ref 赋值延迟到 post-render 队列**（`queuePostRenderEffect`），整树插入完成后才统一设置 ref：

```ts
const mountElement = (vnode, container) => {
  const el = createElement(vnode.type)
  mountChildren(vnode.children, el, ...)    // 子元素挂载，ref 不在此触发
  hostInsert(el, container)                  // 插入父链
  // ref 不在此处设，而是排队到 post-render
  invokeDirectiveHook(vnode, ...)            // 仅指令钩子
}
// post-render 阶段（组件 effect flush 完成后）：
//   setRef(vnode.props.ref, vnode.el)       // 此时整树已插入→isConnected=true
```

### 对比表

| 框架 | 插入顺序 | ref 触发时机 | isConnected |
|---|---|---|---|
| **React** | **前序**（先插入父、再处理子） | commit 阶段，inline | ✅ `true` |
| **Vue 3** | **后序**（先挂子、再插入父） | **defer 到 post-render** | ✅ `true` |
| **ActView** | **后序** | **inline、后序** | ❌ `false` |

两个主流的共同选择是**确保 ref 回调时元素已连接**（React 靠前序插入，Vue 靠延时赋值）。ActView 两者都不占，这是与生态的真实偏差。

---

## 影响范围

- **复合组件模式**（如 CompositeList/Radix 风格），ref 回调内通过 `isConnected` 判断节点是否已挂载 → 挂载期恒判断为"未挂载" → 逻辑静默丢失
- **依赖 isConnected 的守卫模式**在 React / Vue 中可靠，在 ActView 中不可靠
- **不产生崩溃**，但导致开发者的"按惯例写的守卫"在 ActView 下表现不同，产生难定位的 bug

---

## 修复方案

### 方案 A（✅ 已采纳：改动最小，前序插入）

将 `container?.appendChild(el)` 提前到 `patchChildren` 之前（前序插入），使子元素 ref 触发时当前宿主元素已在容器中：

```diff
- patchChildren(…)   // 子挂载 → 子 ref 触发（此时游离）
- container?.appendChild(el)
+ container?.appendChild(el)  // 先插入父
+ patchChildren(…)            // 再挂子 → 子 ref 触发（已连接）
  applyRef(vnode.props?.ref, el)
```

**优点**：改动仅 4 行，仅影响 `mountVnode` 宿主元素分支，无新基础设施。
**风险**：挂载期间子元素可以通过 `querySelector` 找到父节点（React 同语义，目前 ActView 中不可行——已有代码不太可能依赖这个）。全量回归已通过。
**语义说明（采纳时修正论证）**：方案 A 是**前序插入 + ref inline 触发**——ref 回调触发时祖先链已连接（`isConnected=true`），但该元素的**后续兄弟/后代尚未挂载，子树部分可见**（`querySelectorAll`/`children.length` 看到的是部分子树）。这与 React/Vue 的"整树插入完成后统一设 ref"（ref 触发时子树完整）**不同**——React 实际是在 mutation 阶段全部 placement 之后、layout 阶段 `commitAttachRef` 统一触发，与 Vue 3 的 post-render defer 殊途同归。方案 A 只是解决 `isConnected` 时序，未完全复刻主流框架的 ref 触发时机。
**对齐目标**：仅对齐"ref 触发时祖先链已连接"这一可观察结果（React/Vue 亦然）。

### 方案 B（对齐 Vue 3）

将 `applyRef` 的调用收集到 post-flush 队列，整树插入完成后统一执行。需要新的 "ref 队列" 基础设施。

**优点**：保持后序插入不变，ref 触发时机与 Vue 3 一致。
**代价**：新基础设施（`queuePostFlushEffect` 或类似），ref 延迟设置意味着某些同步依赖 ref 的代码（如 `onMounted` 内读 ref）也需要等。

```tsx
  function App() {
    return (
      <div>

          <button ref={(n) => logs.push({ isConnected: n.isConnected })}>x</button>
        </div>
      </div>
    )
  }
  mount(App)
  expect(logs[0].isConnected).toBe(true)  // 修复后应为 true
})
```
